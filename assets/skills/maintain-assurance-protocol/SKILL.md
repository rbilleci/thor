# Maintain Assurance Protocol

<!-- thor:definitions: assurance-results, slice-identity -->

{{definition_bundles}}

Edit only requested protocol contracts. Keep the dispatcher limited to assignment, optional updates, decision-response relay, terminal handling, and the no-workflow-file rule. Do not move maintenance governance into dispatcher or runtime agent prompts.

Require the dispatcher to define the requirements baseline as the independently verifiable outcome, scope, non-goals, constraints, and acceptance criteria. Require each `ASSIGNMENT` to include that baseline, decision authority, dependencies, base commit, assigned branch, checkout, and a new slice identifier. Before sending it, require the dispatcher to verify that the current branch equals the assigned branch, `HEAD` equals the base commit, and `git status --porcelain` is empty; on failure, require `BLOCKED` without altering the checkout. Require the dispatcher to launch one `slicer` subagent as the Slice Owner and make it the checkout’s only writer. Prohibit another Git worktree or branch.

Apply the frozen-candidate definition above. Require the Slice Owner to commit the candidate on the current branch before assurance and `COMPLETE`, pause writes throughout systemic review and the complete focused wave, and verify the recorded commit and clean checkout before accepting a result. Before `COMPLETE`, require the Slice Owner to verify the reviewed candidate and a clean checkout. Require the next slice to use the completed commit as its base. Do not model candidate handoff through trees, merges, snapshot machinery, or another checkout.

Keep the slicer’s conditional conversational preflight. Require the slicer to assess only applicable material surfaces and authoritative contracts before coding, create neither a preflight agent nor an inventory artifact, and resolve material omissions. Require it to continue the same active slice after a resumable platform pause and return `BLOCKED` after the platform reports a non-resumable interruption. Where an authoritative source governs authorization, interface or Application Programming Interface (API), schema, migration, or compatibility rules, require the slicer to derive implementation from that source or validate with repository-native gates. Limit the resolver to governing conflicts, undefined material public behavior, and authority boundaries. Do not add a generic governance manifest.

Permit one `ASSIGNMENT`, zero or more `UPDATE`s, and one `TERMINAL` per slice. Route `ASSIGNMENT` to the Slice Owner and route its messages back for the same slice. Limit `UPDATE` to freeze or review start, repair start, blocker or decision, or requested status. For a decision `UPDATE`, require the dispatcher to relay the assigned decision authority's exact response to the retained owner. Require the response to identify the slice, reviewed candidate, and exact finding; state the resulting constraint; and give its basis. Prohibit inferred authority decisions. Require `TERMINAL` to certify that neither the owner nor started work can write to the checkout. Verify each message against the active assignment and require a candidate commit for `COMPLETE`. Retain the assignment until accepting `TERMINAL` or completing confirmed owner-loss handling. Clear it before another `ASSIGNMENT`. Do not persist workflow state or reports.

Retain one end-to-end Slice Owner per slice, a frozen commit, a mandatory independent systemic gate, a resolver, focused auditors, fast validation during editing, and slower validation after stabilization. Require systemic assurance to review raw candidate and independently established evidence first, without any previous reviewer conclusion, and to inspect every relevant authoritative document and implementation surface needed for a complete system-wide determination. Require systemic assurance to evaluate end-to-end relationships and emergent behavior, and focused reviewers to evaluate lens-owned invariants. Require every reviewer to report only evidenced failures that materially affect the supplied outcome or an applicable contract in the current context and to omit minor, speculative, theoretical, and hardening-only concerns. Permit systemic and focused review to inspect the same evidence, but prohibit the systemic determination from substituting for focused review of a materially changed lens-owned invariant. Require the systemic reviewer to produce a focused review plan only when `Findings` and `Evidence Gaps` are both `None`, and require the smallest sufficient lens set. Select a lens only when the candidate materially changes a directly owned behavior, contract, or invariant, supplied evidence makes a concrete failure mode reachable, the consequence would materially affect the outcome or an applicable contract, and the lens supplies an independent specialized determination of that distinct risk. When risks overlap, select the lens that most directly owns the root failure and omit lenses that would review only another consequence of the same causal sequence; another planned lens justifies omission only when the omitted lens owns no separate changed material invariant. Prohibit selection based only on an imaginable issue, related files, technologies, keywords, hypothetical future scale, missing evidence, or cross-boundary effects. Permit `Selection: None` only when the candidate materially changes no focused lens-owned invariant. Require missing evidence to produce an evidence gap instead of broader selection. Require every finding to enter `REPAIR` or `DECISION` resolution, and restart systemic assurance for every replacement candidate.

After a matching systemic pass, require the Slice Owner to accept the plan only when it names distinct canonical reviewers, provides the four-part trigger and distinct contribution for every selection, rejects overlapping consequence-only selections, and provides candidate-specific omission evidence that each unselected lens owns no materially changed invariant or owns only a secondary consequence of a root failure directly owned by a planned lens. Reject systemic coverage as omission evidence. Prohibit the Slice Owner from adding, removing, or substituting reviewers. When the plan selects reviewers, require one focused wave containing every planned auditor for the frozen candidate. Require the owner to start members until no agent execution slot remains, keep unstarted members pending in the same wave, and start one whenever the platform reports an available slot before later assurance work. Lack of slots must not split the wave, change its candidate, permit omission, or constitute failure. Define eventual start and join as conditional on the platform eventually reporting capacity and reviewer completion or inability; prohibit a claim of platform liveness while it supplies none. During an external stall, retain pending members, keep the candidate immutable, and prohibit repair or `COMPLETE`. Give each member only needed raw evidence, withhold the systemic-review conclusion, require an exact candidate match and reviewed revision, and retain early results. Define wave completion as every member returning a matching result. Require the Slice Owner, not the systemic reviewer, to reconcile overlapping focused findings after the complete wave. Do not cancel or delay a pending member because another reports a finding. Require each auditor to return `Findings` and `Evidence Gaps`; resolve each gap, then require a fresh matching result. Restart systemic assurance if new evidence changes plan applicability. If the platform reports that a planned auditor cannot start or return, require completed stop handling and `BLOCKED` unless that auditor supplied a matching result. Skip the wave only when the plan proves that the candidate materially changes no focused lens-owned invariant.

After a systemic finding result or complete focused wave with findings, require the Slice Owner to deduplicate equivalent findings and group `REPAIR` findings by root cause and dependency. Apply all mutually compatible authorized groups in one repair batch; separate groups only for conflict, dependency, or isolated validation needed for a defensible result. Serialize all repair writes. Route `DECISION` findings through the resolver when triggered. Before applying `RESOLVED`, require a matching base, candidate, and exact finding. Require the Slice Owner to produce, validate, and commit a compliant replacement candidate for every repair or authority decision, then restart assurance with systemic review. Keep the Slice Owner as the checkout’s only writer.

Require `COMPLETE` to have matching systemic and planned focused results with `Findings: None` and `Evidence Gaps: None` for the reviewed candidate. When `Selection` is `None`, require only the systemic pass.

If a called role cannot return, require the Slice Owner to request a platform stop and return `BLOCKED`. Require the dispatcher to keep the active Slice Owner running until `TERMINAL`, continue the same Slice Owner when the platform can resume it, and not treat elapsed time, absence of an `UPDATE`, or a resumable platform pause as owner loss. When the platform reports that the retained Slice Owner cannot continue the active slice, require the dispatcher to request a platform stop for that owner and slice. Start no other writer until the platform confirms that the retained Slice Owner and all work it started, directly or indirectly, can no longer write to the checkout. Treat any other confirmation as missing, require `BLOCKED`, and preserve the checkout. If the Slice Owner returns `TERMINAL` before confirmation, require the dispatcher to handle that result and ignore later stop confirmation. Otherwise, after confirmation, require the dispatcher to rerun the original admission checks. If they pass, require the dispatcher to clear the assignment and assign the outstanding outcome as a new slice. If they fail, require `BLOCKED` with the failed check and preserve the checkout. Do not create retry scheduling or recovery state.

Measure complete files with `wc -w`. Keep every generated agent definition at or below 2000 words. Report each actual count as delivery evidence. Thor generates Codex agents in `.codex/agents`, Codex skills in `.agents/skills`, and Claude agents and skills in `.claude`. Edit only `assets/`; do not hand-edit generated output. Keep word, line, and size limits only in this maintenance skill.

Before freeze, run `git diff --check`, `cargo run --locked -p thor-build -- validate`, `cargo run --locked -p thor-build -- transform`, and `cargo run --locked -p thor-build -- transform --check`. Parse every `.codex/agents/*.toml` with Python 3 `tomllib`, verify changed paths, measure word counts, search contracts for candidate-freeze contradictions and prohibited scheduling or checkout-lifecycle terms, and prove no agent or dispatcher mentions word, line, or size limits. Do not create a validator script.

Obtain a fresh systemic review from raw candidate evidence, then run the focused reviewers in its matching plan. Verify systemic depth, smallest-sufficient selection with the four-part threshold and distinct contribution, candidate-specific omissions, simplicity, quality, efficiency, message and state limits, capacity-aware concurrent read-only waves with serialized repair writes, and absence of workflow artifacts. Require the dispatcher to request a `DECISION_REQUIRED` decision and report a `BLOCKED` clearing condition or `FAILED` criterion with evidence. After `DECISION_REQUIRED` or `FAILED`, prohibit another `ASSIGNMENT` until the user authorizes the next action. After `BLOCKED`, prohibit another `ASSIGNMENT` until objective evidence proves every reported condition cleared or the user authorizes an alternative that avoids those conditions. User authorization cannot waive assignment retention or unresolved owner-loss confirmation. Require clean admission and a new slice for follow-up. Repair material defects without adding lifecycle or identity machinery.

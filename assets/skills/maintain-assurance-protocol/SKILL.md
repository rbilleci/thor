# Maintain Assurance Protocol

<!-- thor:definitions: assurance-results, slice-identity -->

{{definition_bundles}}

Edit only requested protocol contracts. Keep the dispatcher limited to assignment, optional updates, terminal handling, and the no-workflow-file rule. Do not move maintenance governance into dispatcher or runtime agent prompts.

Require the dispatcher to define the requirements baseline as the independently verifiable outcome, scope, non-goals, constraints, and acceptance criteria. Require each `ASSIGNMENT` to include that baseline, decision authority, dependencies, base commit, assigned branch, checkout, and a new slice identifier. Before sending it, require the dispatcher to verify that the current branch equals the assigned branch, `HEAD` equals the base commit, and `git status --porcelain` is empty; on failure, require `BLOCKED` without altering the checkout. Require the dispatcher to launch one `slicer` subagent as the Slice Owner and make it the checkout’s only writer. Prohibit another Git worktree or branch.

Apply the frozen-candidate definition above. Require the Slice Owner to commit the candidate on the current branch before assurance and `COMPLETE`, pause writes during review, and verify the recorded commit and clean checkout before accepting a result or `COMPLETE`. Require the next slice to use the completed commit as its base. Do not model candidate handoff through trees, merges, snapshot machinery, or another checkout.

Keep the slicer’s conditional conversational preflight. Require the slicer to assess only applicable material surfaces and authoritative contracts before coding, create neither a preflight agent nor an inventory artifact, and resolve material omissions. Require it to continue the same active slice after a resumable platform pause and return `BLOCKED` after the platform reports a non-resumable interruption. Where an authoritative source governs authorization, interface or Application Programming Interface (API), schema, migration, or compatibility rules, require the slicer to derive implementation from that source or validate with repository-native gates. Limit the resolver to governing conflicts, undefined material public behavior, and authority boundaries. Do not add a generic governance manifest.

Permit one `ASSIGNMENT`, zero or more `UPDATE` messages, and one `TERMINAL` per slice. Route `ASSIGNMENT` from the dispatcher to the Slice Owner. Route `UPDATE` and `TERMINAL` back only from that owner for that slice. Limit `UPDATE` to freeze or review start, repair start, a blocker or decision, or user-requested status. Require `TERMINAL` to certify that neither the owner nor started work can write to the checkout. Require every message to name its slice identifier. Verify each `TERMINAL` against the active assignment. Require a candidate commit for `COMPLETE`; verify any candidate reported for another status. Retain the active slice identifier, Slice Owner, checkout, base commit, assigned branch, and dependencies until accepting `TERMINAL` or until the platform confirms that the owner cannot continue and the original admission checks pass. Clear the assignment before another `ASSIGNMENT`. Do not persist workflow state or reports.

Retain one end-to-end Slice Owner per slice, a frozen commit, an independent selector, a resolver, independent auditors, fast validation during editing, slower validation after stabilization, and systemic assurance when the selector requires it. Require the selector to choose at least two independent auditors, including intent and scope plus verification and change safety for every slice. Require the Slice Owner to invoke the selector, every selected auditor, and systemic assurance in sequence. Require each auditor to return the structured assurance result with its reviewed revision, `Findings`, and `Evidence Gaps`; a passing result uses `None` for both headings. Require each finding to use `REPAIR` or `DECISION` classification.

If a called role cannot return, require the Slice Owner to request a platform stop and return `BLOCKED`. Require the dispatcher to keep the active Slice Owner running until `TERMINAL`, continue the same Slice Owner when the platform can resume it, and not treat elapsed time, absence of an `UPDATE`, or a resumable platform pause as owner loss. When the platform reports that the retained Slice Owner cannot continue the active slice, require the dispatcher to request a platform stop for that owner and slice. Start no other writer until the platform confirms that the retained Slice Owner and all work it started, directly or indirectly, can no longer write to the checkout. Treat any other confirmation as missing, require `BLOCKED`, and preserve the checkout. If the Slice Owner returns `TERMINAL` before confirmation, require the dispatcher to handle that result and ignore later stop confirmation. Otherwise, after confirmation, require the dispatcher to rerun the original admission checks. If they pass, require the dispatcher to clear the assignment and assign the outstanding outcome as a new slice. If they fail, require `BLOCKED` with the failed check and preserve the checkout. Do not create retry scheduling or recovery state.

Measure complete files with `wc -w`. Keep every generated agent definition at or below 1000 words. Report each actual count as delivery evidence. Thor generates Codex agents in `.codex/agents`, Codex skills in `.agents/skills`, and Claude agents and skills in `.claude`. Edit only `assets/`; do not hand-edit generated output. Keep word, line, and size limits only in this maintenance skill.

Before freeze, run `git diff --check`, `cargo run --locked -p thor-build -- validate`, `cargo run --locked -p thor-build -- transform`, and `cargo run --locked -p thor-build -- transform --check`. Parse every `.codex/agents/*.toml` with Python 3 `tomllib`, verify changed paths, measure word counts, search contracts for candidate-freeze contradictions and prohibited scheduling or checkout-lifecycle terms, and prove no agent or dispatcher mentions word, line, or size limits. Do not create a validator script.

Obtain fresh selector-chosen reviews from raw candidate evidence, including mandatory intent and scope plus verification and change safety. Verify simplicity, independent audit selection, quality, efficiency, message and state limits, serial scheduling, and absence of workflow artifacts. Require the dispatcher to request a `DECISION_REQUIRED` decision and report a `BLOCKED` clearing condition or `FAILED` criterion with evidence. After `DECISION_REQUIRED` or `FAILED`, prohibit another `ASSIGNMENT` until the user authorizes the next action. After `BLOCKED`, prohibit another `ASSIGNMENT` until objective evidence proves every reported condition cleared or the user authorizes an alternative that avoids those conditions. User authorization cannot waive assignment retention or unresolved owner-loss confirmation. Require clean admission and a new slice for follow-up. Run systemic assurance once when the selector requires it. Repair material defects without adding lifecycle or identity machinery.

# Maintain Assurance Protocol

## Scope and authority

Edit only requested protocol contracts. Keep the Work Dispatcher limited to assignment, compact updates, terminal handling, and determining an escalated finding’s materiality or selecting only among Architect-supplied interpretations when that preserves the requirements baseline and every applicable contract. External authority decides every other baseline or contract change. The Dispatcher does not invoke the Architect, design, implement, review, select reviewers, accept risk, extend rounds, or direct another writer. It waits for and messages only the retained Slice Owner, except for platform-confirmed owner-loss diagnosis or stop confirmation.

Define the requirements baseline as outcome, scope, non-goals, constraints, and acceptance criteria. Require each assignment to include that baseline, decision authority, dependencies, base, branch, checkout, and slice identifier without restating the slicer protocol. Before assignment, require assigned branch, base, and clean status to match. One Slice Owner writes one shared checkout; do not create a worktree, branch, workflow artifact, generic governance manifest, validator script, retry state, or report.

## Architecture and evidence

Require one fresh read-only Architect after admission and before the first checkout mutation. It receives complete baseline, authority, dependencies, base, instructions, documents, implementation, operations, and discovery. Require matching outcome and base, exactly one supported status, singleton required sections, complete plan, generated-output consequences, ownership, constraints, validation obligations, and no unresolved gap for a ready result. A ready result constrains implementation but never certifies it. Ordinary implementation, generation, validation, and repair within accepted design do not invoke the Architect. Re-architect only after material invalidation of responsibility, contract, ownership, trust, lifecycle, concurrency, deployment, recovery, validation, accepted evidence, baseline, or base.

Require the Architect to determine the complete applicable focused-lens partition in every ready result. Every selected canonical focused reviewer states its directly owned materially changed behavior or invariant, reachable candidate-specific failure, material consequence, and distinct specialized contribution. Every omitted canonical reviewer states evidence that it owns no materially changed invariant or only a secondary consequence of a selected root failure. `Selection: None` requires all canonical focused lenses in omissions and no changed focused invariant. The Systemic Assurance Reviewer is mandatory systemic membership and is not a focused selection. The Slice Owner verifies the partition and may not add, remove, or substitute reviewers.

Validate accepted Architect results through the trusted platform channel. Create a unique temporary artifact outside checkout, write exact UTF-8 once, calculate and reread-verify SHA-256, close writes, and retain only reference and digest locally. Never replace in place. A create, write, reread, verification, or close failure cleans partial output, pauses writes, and permits exactly one new-location replacement; replacement failure cleans output and blocks. Retain ready artifacts through readers. Readers receive only reference and digest, verify digest and identity, and report inaccessible, missing, mismatched, malformed, or wrong-identity evidence as a gap. Missing active evidence invalidates dependent assurance and requires fresh Architect evidence. Delete artifacts only after readers return or stop; preserve existing resumable and non-resumable cleanup and platform-failure routes. Never include result content, reference, or digest in Dispatcher-bound messages.

`DECISION_REQUIRED` and `INDETERMINATE` do not authorize mutation. An Architect decision request contains only bounded question, interpretations, constraints, and consequences. Before round-three assurance-wave start, Dispatcher applies a valid matching determination once per unresolved context; exact duplicates are no-ops and nonidentical determinations are rejected. After round-three wave start, reject every decision delivery. `INDETERMINATE` needs named no-edit evidence and one fresh Architect; an unavailable or repeated result blocks. An authoritative decision requires fresh Architect evidence.

## Candidate, reviews, and rounds

Treat workflow agents and platform results as trusted but fallible. Verify identity, completeness, evidence consistency, and behavior; assess correctness rather than hypothetical malice unless evidence changes the trust boundary. A frozen candidate contains the baseline, base, and complete commit. The Slice Owner commits it before assurance and completion; identity changes invalidate evidence. Pause writes during every assurance wave and verify branch, candidate, and clean checkout before accepting results.

A finding proves that the exact candidate violates a named acceptance criterion, invariant, or applicable contract in a feasible scenario. It names the requirement, candidate connection, observable failure, and acceptance consequence. Classify it as `REPAIR` or `DECISION`. Record exact missing or conflicting facts as `Evidence Gaps`, not unproved findings. Preference, speculation, hardening, or severity alone is not a finding.

One assurance wave contains exactly `systemic-assurance-reviewer` and the Architect-selected focused reviewers for one frozen candidate. Start members from raw candidate and independently established evidence until capacity exhausts; retain pending members in the same wave and start each when capacity returns. No reviewer receives another conclusion. The systemic reviewer independently determines system-wide invariants, handoffs, compound transitions, emergent behavior, redesign defects, and coverage gaps, but does not plan, select, omit, gate, add, schedule, or sequence reviewers. No early finding or gap may cancel, delay, split, or sequence the wave. Keep the candidate immutable through stalls. Wait for a matching result from every member; resolve a gap with a fresh matching result from the affected reviewer. A member unable to start or return requires stop handling and `BLOCKED` unless it returned a match. Reconcile overlaps only after the complete wave. A wave passes only when every matching result has no findings and no gaps. `Selection: None` makes systemic the sole member.

One review-and-repair round is one fresh assurance wave for one candidate. A completed-wave finding is the stopping result; gap resolution, same-candidate correction, extra validation, and duplicate determinations remain in that round. Start round one with the initial wave and advance only when starting a fresh wave for a validated committed repair replacement. In rounds one and two, mechanically verify each finding, deduplicate by root cause and dependency, repair compatible authorized findings in one serialized batch, validate, commit one replacement, and re-review. Before round three, route only genuine materiality disputes and Architect-supplied interpretations through the bounded Dispatcher window. In round three, every complete baseline-preserving finding is a repair obligation without materiality escalation; repair compatible obligations in one serialized validated batch, create a terminal direct-child commit, map every finding to change and validation, and complete without post-repair review. Return `FAILED` for conflict, demonstrated infeasibility, or required outside authority, and `BLOCKED` for missing evidence, unusable roles, platform failure, or unavailable validation. Never start a fourth round.

`matching-pass` requires clean matching results from every member of the terminal candidate’s Architect-constrained wave. `final-repair` identifies the reviewed round-three commit and a clean validated direct-child terminal commit with complete finding-to-change-to-validation mapping, and states that no matching independent pass exists. Preserve materiality, raw-evidence independence, candidate identity, security, artifact, stop, cleanup, and single-writer guarantees.

## Protocol messages and maintenance

Permit one assignment, zero or more updates, and one terminal per slice. Every update has `Slice`, `Phase`, `Candidate`, and `Attention` exactly once; phase is `freeze`, `review-start`, `repair-start`, `blocker`, `decision`, or `status`. Send updates only for those events. A decision update adds only a reference-free raw finding and governing evidence or the bounded Architect request. Terminal handling validates the assignment envelope and matching-pass or final-repair basis without conducting assurance. The terminal certifies that neither the owner nor started work can write. Preserve active assignment until terminal acceptance or confirmed owner-loss handling.

Edit only `assets/`; generate projections through Thor. Keep generated agent definitions at or below the repository limit measured by `wc -w`; report actual counts. Before freeze, run `git diff --check`, `cargo run --locked -p thor-build -- validate`, `cargo run --locked -p thor-build -- transform`, and `cargo run --locked -p thor-build -- transform --check`. Parse every Codex agent TOML with Python 3 `tomllib`, verify changed paths, and search source and generated contracts for obsolete role names, candidate-freeze contradictions, prohibited scheduling or checkout-lifecycle terms, and forbidden size-limit references outside this maintenance skill.

For an assurance-protocol change, verify source and generated contracts retain trusted-but-fallible handling, fresh Architect-before-mutation, all four Architect statuses, accepted-result implementation, material-invalidation re-architecture, no implementation certification, write-once artifact lifecycle, reference/digest reader handoff, cleanup, dispatcher leakage prohibition, exactly-once decisions, round identity, direct-child final repair, and no fourth round. Verify the Architect owns exhaustive applicable-lens selection and omissions; systemic output has only revision, findings, and evidence gaps; all wave members start capacity-aware from raw evidence without conclusions or gating; every matching member must return before repair or completion; and `Selection: None` remains systemic-only only when Architect selected it. Verify no source or generated contract retains the removed decision role. Run formatter, strict Clippy, workspace tests, build, build validation, transform checks, and the complete matching assurance wave selected by the accepted Architect result. Do not create a validator script. Repair material defects without adding lifecycle or identity machinery.
